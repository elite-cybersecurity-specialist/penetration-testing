# Security References and Assessment Frameworks

[← Back to main page](../README.md)

Our company profile describes framework-informed testing and defensive verification. Frameworks are **selected according to the target technology, risk profile and client objectives**, not applied as one universal checklist.

| Reference | Potential use in security assessment |
|---|---|
| OWASP Top 10 | Prioritize familiar classes of web application risk. |
| OWASP Web Security Testing Guide (WSTG) | Organize relevant web application verification activities. |
| OWASP Application Security Verification Standard (ASVS) | Deepen application security requirements and testing coverage. |
| OWASP API Security Top 10 | Evaluate API authorization, identity, data exposure and abuse risks. |
| MITRE ATT&CK | Map relevant attacker behaviors and likely defensive control gaps. |
| CIS Controls and Benchmarks | Review configuration and hardening exposures on relevant technology. |
| DISA STIG / Security Requirements Guides | Inform high-security configuration objectives where appropriate. |
| NIST Cybersecurity Framework 2.0 | Frame security outcomes across Govern, Identify, Protect, Detect, Respond and Recover. |
| NIST SP 800-53 | Relate technical findings to security-control families where appropriate. |
| NIST SP 800-115 | Technical security testing and assessment process guidance. |
| NIST SP 800-207 | Zero Trust concepts and access-control boundaries. |
| NIST SP 800-218 / SSDF | Secure development and dependency security considerations. |
| CISA Secure by Design | Security-oriented product and deployment design principles. |
| ISO/IEC 27001 and 27002 principles | Relevant organizational security and information protection context. |

**Important distinctions:**

- Citing or mapping a standard is not proof of formal certification, independent accreditation or comprehensive compliance.
- DISA STIG / SRG-inspired hardening objectives are not represented as DISA authorization.
- OWASP, NIST and MITRE provide reference material; they do not endorse individual ECS engagements.
- Exact standard versions and relevant test sections should be captured in each signed engagement plan.

Reference websites: [OWASP](https://owasp.org/) · [NIST](https://www.nist.gov/cyberframework) · [MITRE ATT&CK](https://attack.mitre.org/) · [CIS](https://www.cisecurity.org/)
