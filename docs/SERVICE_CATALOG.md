## Purpose and Engagement Models

We examine authorized systems from an attacker's perspective and provide remediation guidance and verification. **WHITEBOX**, **GRAYBOX**, and **BLACKBOX** testing describe how much information or access the assessor receives; each can be applied to appropriate systems. Scope is negotiated per customer and may combine methods.

| Model | Information provided | Typical focus |
|---|---|---|
| Whitebox | Full or extensive internal information as authorized | Architecture, source review, configuration and internal trust boundaries |
| Graybox | Restricted information or approved low-privilege identities | Authenticated user journeys and partially trusted scenarios |
| Blackbox | Little or no internal information | Exposed services and externally observable weakness discovery |

## Detailed Security Assessment Areas

### 1. Web Application Testing

Assess authentication, authorization, session management, injection exposure, input validation, configuration, sensitive-data handling and relevant business logic. The goal is to identify exploitable conditions and their business implications, not simply enumerate automated alerts.

### 2. API Security Testing

Examine API access-control rules, identity and token handling, endpoint authorization, excessive data exposure, rate protections, cross-service trust, input handling and abuse scenarios. Requires approved APIs, environments and test accounts where applicable.

### 3. Authentication & Access Control

Review login defenses, password and session protections, MFA enforcement, controlled lockout/abuse resistance and access between ordinary, privileged and service identities. Aggressive authentication attempts are conducted only within expressly agreed limits.

### 4. Server Security Testing

Inspect externally or internally exposed services, patch/upgrade state, administrative access, service configuration, privileges, identity separation, logging and exposed management interfaces. Read-only or minimally intrusive verification is preferred for production systems.

### 5. Network Penetration Testing

Investigate approved host and service exposure, insecure protocols, segmentation and firewall enforcement, remote access and unintended trust pathways. Routes into other networks or third-party assets require separate permission.

### 6. Wireless Security Testing

Examine authorized Wi-Fi deployments, access-point security, authentication/encryption, connected-device isolation, guest separation and relevant wireless configuration. Spectrum, location and disruption restrictions are included in the Rules of Engagement.

### 7. Mobile Application Testing

Assess agreed Android and iOS applications for storage, transport, authentication, authorization, API usage and sensitive-information handling. Device and app test configuration depend on platform and engagement boundaries.

### 8. CCTV Security Testing

Review approved IP camera, VMS and NVR environments for credentials, management exposure, authentication, APIs, insecure network access, segmentation, firmware and remote access. Service availability and image/data privacy require special safeguards.

### 9. IoT Security Testing

Assess authorized connected devices and embedded products, exposed network services, access control, supporting platforms and device-to-backend trust relationships. Firmware modification or hardware manipulation is not included unless separately approved.

### 10. Social Engineering Assessment

Use explicitly agreed scenarios to examine human security controls and escalation/reporting processes. The client must approve participants, channels, prohibited scenarios and wellbeing safeguards. No unauthorized employee targeting.

### 11. Phishing Simulation

Perform bounded, client-approved awareness and response exercises with clear purpose, stakeholder approval, minimal data collection and agreed metrics. This is not a default component of ordinary penetration testing.

### 12. Physical Security Testing

Assess facility or device-access controls only under separate, explicit written authorization. Set limits on sites, times, conduct, escalation, safety and response from facility/security personnel before performing activities.

## Cross-Cutting Assessment Work

**Vulnerability validation:** Confirm important findings using controlled methods and record the conditions, potential impact and confidence.

**Remediation recommendations:** Describe feasible control improvements and affected responsibilities without implying that every remediation is automatically included in the assessment fee.

**Final re-testing:** Verify agreed fixes, report remaining weaknesses, and distinguish **resolved / partially resolved / open / not re-tested** states.

## Availability and Limitations

Capabilities listed represent the service areas described in the company profile, not an unconditional commitment to test every technology, attack technique, jurisdiction or physical location. Resource availability, client authorization, specialist equipment, data handling, contractual scope and operational risk determine the final engagement.
